# Independent audit and re-analysis, 20 November 2026

This note records an independent code, data, statistical and manuscript audit of
the JIWE submission derived from this repository, and the corrections that
followed from it. It is committed so that the repository, the manuscript and the
experiment archive describe the same system.

## What the audit found

The controlled evaluation reproduces exactly. Every RQ1 number is recoverable
from archived records, and the source partitions contain no leakage: 987 sources
split 691 / 148 / 148, the 95-source locked set and the 53-source replication set
together account for the 148-source test partition, and the 40-source
calibration subset is disjoint from both.

The field-level analysis did not reproduce. The support evidence was computed in
the 8 November 2026 run and the correctness labels in the 13 November 2026
agreement run; no archived artefact joined them. The two correctness definitions
also disagree on 125 of the 570 high-risk fields (98 wrong-to-right, 27
right-to-wrong). Four method sentences described behaviour the code does not
implement, and the first of two fresh real-receipt tests — which showed no
advantage — was not reported.

## What was corrected

`scripts/rq2_rq3_reanalysis_20261120.py` re-runs both field-level analyses inside
a single archived configuration, using the same score definition, isotonic fit,
validation selection rule, matched-coverage construction and bootstrap as
`scripts/final_evaluation_20261107.py`. It needs no cross-run join, because the
validation and test partitions of the 8 November run are used together.

The consequence is a substantive correction rather than a cosmetic one. Under
the single-configuration analysis the composite field score is better calibrated
than OCR confidence (ECE 0.054 against 0.069) and better at ranking (AUC 0.884
against 0.799). The previously reported worse-than-OCR calibration appears only
when pre-agreement scores are evaluated against post-agreement labels (ECE 0.079
against 0.059). Both variants are now reported; the primary one is the
internally consistent one.

Two claims are withdrawn rather than corrected, because neither could be produced
from any archived configuration: the re-selected-threshold analysis that reported
59.6% coverage with accepted accuracy of 0.762, and the statement that only the
proposed policy collapsed at the planned thresholds. Under the coded score
definitions all three policies accept zero fields at all three planned pairs.

The zero-coverage result is also stronger than previously stated. The composite
is `0.45 * support + 0.35 * c_ocr + 0.20 * rule`, so it cannot exceed
`0.45 * max(support) + 0.55`. With realised support maxima of 0.505, 0.518 and
0.525 the bound is 0.777, 0.783 and 0.786, all below the smallest planned
acceptance threshold of 0.80. The policy was arithmetically incapable of
accepting any field, for any calibration map. This is a specification error and
should be fixed in the acceptance design, not attributed to the data.

## What remains for the author

1. Re-run support, OCR confidence, rule and localisation on the *voted* field so
   that the deployed configuration can be evaluated. Until then no claim about
   the deployed system's calibration is available from the archive.
2. Fix the acceptance specification: either lower the thresholds to the realised
   score range or renormalise the weights so the score can span the decision
   range.
3. Add a materials reference for the thermal-paper degradation claim, and a
   reference for OCR confidence as an error-detection signal; both claims are
   currently uncited rather than cited to an unverified source.
4. Confirm the bibliographic details of the 38 references now in the manuscript,
   in particular the TCSVT volume and page numbers for the DSDNet paper.

## Submission-stage verification

A second pass checked the manuscript as a document rather than as a set of
claims, and three defects that the first pass could not see were found and
fixed: three values were rounded up rather than to nearest (the q20 support
maximum, the q20 composite bound, and one confidence-interval lower bound); no
table was cited in the running text, only in its caption; and the
reproducibility paragraph was written in the future tense about artifacts that
did not yet exist.

That last defect is now closed by construction. `artifacts/SHA256SUMS` lists the
SHA-256 digest of every public configuration, experiment manifest, re-analysis
script and aggregate output, so the manuscript's reproducibility claim can be
checked against the repository rather than taken on trust. Two scripts make the
verification repeatable:

```bash
python scripts/final_consistency_check_20261120.py   # structure, withdrawn claims, citations
python scripts/numeric_reconciliation_20261120.py    # every reported statistic vs report.json
```

## Reproducing this audit

```bash
python scripts/rq2_rq3_reanalysis_20261120.py --data-root /path/to/private/repo
python scripts/rq2_rq3_figures_20261120.py \
    --report artifacts/rq2_rq3_reanalysis_20261120/report.json \
    --out artifacts/rq2_rq3_reanalysis_20261120/figures
```

Aggregate outputs only are committed: no receipt images, no per-field rows, no
private paths.
